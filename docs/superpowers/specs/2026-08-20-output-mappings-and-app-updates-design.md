# 输出项独立设置与应用更新设计

日期：2026-08-20
状态：用户已确认界面方向和功能范围

## 1. 目标

本次升级包含两个相互独立但一并交付的功能：

1. 把当前“资金台账/运营台账公共字段设置”升级为按需求文件输出内容逐项配置。
2. 使用 GitHub Releases 发布 macOS 安装包，并让应用检查、下载和打开适合当前芯片的新版 DMG。

用户可以应对工作表名称、表头行、字段名称、筛选字段、筛选值和数值参数变化。程序继续控制计算类型，不支持自由编写公式。

## 2. 设置边界

### 2.1 可以修改

- 两份源工作簿的工作表名称和表头行。
- 每个输出项各自使用的日期字段、筛选字段、筛选值和汇总字段。
- 资金渠道名称、渠道利率、资金成本率和计息天数。
- 自营项目周报每个业务行的显示名称、项目周期和利润率测算内容。
- 自营项目周报每个计算列各自的筛选字段、筛选值和计算字段。

即使两个输出项当前使用同一个源字段，也各自保存输入值，修改一项不会同步修改另一项。

### 2.2 保持固定

- 计算类型仅使用程序内置的计数、求和、比率和资金收益计算。
- 财年、Week、月末拆分、冻结基线、回刷前一周期和漏周补齐规则保持不变。
- 经营汇总中的卡转订单和卡转利润继续固定为零。
- 合计利润继续等于项目预估利润、散采预估利润和资金预估利润之和。
- 目标和完成度沿用现有固定规则。
- 自营项目周报保持现有业务行数量；本次可修改现有行，不增加业务行增删功能。

自由公式、自动猜测近似字段、灰度更新、强制更新和备用下载源不在本次范围内。

## 3. 设置界面

现有“字段设置”入口保留，窗口改为左侧导航和右侧内容区域。正式界面不显示设计说明或教学文字。

左侧只有三个入口：

- 数据源设置
- 经营汇总
- 自营项目周报

底部统一提供“恢复默认”“取消”“保存设置”。保存后，如果主窗口已选择数据源，立即重新校验并清除旧的生成结果。

### 3.1 数据源设置

资金台账：

- 工作表名称，默认 `资金散板汇总{年份}`。
- 字段表头所在行，默认 `1`。

运营台账：

- 工作表名称，默认 `台账明细`。
- 字段表头所在行，默认 `1`。

资金工作表名称中的 `{年份}` 继续按所需自然年替换；不含占位符时按完整名称读取。

### 3.2 经营汇总

右侧按输出项列出“输出内容、数据来源、筛选与计算、设置”。每次只展开一个输出项，避免同时显示大量输入框。

各输出项默认设置如下：

| 输出项 | 数据源 | 独立设置 |
| --- | --- | --- |
| 项目订单数量 | 运营台账 | 日期字段=`预计起飞时间`；项目类型字段=`项目类型`；排除值=`散采`；计数字段=`提单号` |
| 项目预估利润 | 运营台账 | 日期字段=`预计起飞时间`；项目类型字段=`项目类型`；排除值=`散采`；求和字段=`预估毛利润` |
| 散采订单数量 | 运营台账 | 日期字段=`预计起飞时间`；项目类型字段=`项目类型`；包含值=`散采`；计数字段=`提单号` |
| 散采预估利润 | 运营台账 | 日期字段=`预计起飞时间`；项目类型字段=`项目类型`；包含值=`散采`；求和字段=`预估毛利润` |
| 资金放款金额 | 资金台账 | 日期字段=`信容付款日期`；求和字段=`付款金额合计（90%）` |
| 资金预估利润 | 资金台账 | 日期字段=`信容付款日期`；渠道字段=`渠道名称`；金额字段=`付款金额合计（90%）`；操作费字段=`应收操作费`；两个渠道名称和利率；成本率=`4.48%`；计息天数=`60` |
| 卡转订单/利润 | 固定值 | 显示固定为零，不提供源字段输入 |
| 合计利润 | 表内计算 | 显示固定计算关系，不提供源字段输入 |

资金利润默认渠道为现有完整公司名称及 `10%`、`12%` 利率。渠道名称和利率成对编辑；空渠道不允许保存。

### 3.3 自营项目周报

页面显示现有业务行列表：WWP、欧展、金开宇、厦门伦升、印华、美鑫通、迅達航空和散采。选择一个业务行后编辑该行，避免把所有业务和输入框同时铺开。

每个业务行提供：

- 业务名称：输出表中的显示名称。
- 项目周期：输出表中的显示文字。
- 利润率测算：可填写百分比、普通文字或留空；保存时保留其类型和显示格式。
- 完成数量：日期字段、最多三个“筛选字段/筛选值”输入对、计数字段。
- 预估利润：日期字段、最多三个独立筛选输入对、求和字段。
- 预估利润率：日期字段、最多三个独立筛选输入对、分子字段和分母字段。

筛选输入对的规则：字段和值同时为空表示不使用该筛选；只填写一边时不能保存。默认值按需求文件设置：

- 普通业务使用 B1 供应商字段和值。
- 印华 OSL、ORD、LGG 增加目的口岸筛选。
- 欧展固定位和差价增加项目类型筛选。
- 散采使用项目类型筛选。

完成数量、预估利润和预估利润率的日期及筛选输入完全独立。预估利润率固定为分子字段求和除以分母字段求和；分母为零时继续输出空值。

合计行单独配置：

- 显示前缀，默认 `销售额合计`。
- 销售额字段和日期字段，用于标题中的销售额合计。
- 完成数量、预估利润和预估利润率各自使用独立字段和筛选输入。

## 4. 数据与计算

### 4.1 配置保存

继续使用现有应用数据目录和 JSON 原子写入方式，不新增数据库或依赖。配置增加明确的结构版本。

读取旧版 `source-fields.json` 时自动迁移：

- 工作表名称和表头行直接保留。
- 每个旧公共字段复制到所有当前依赖它的输出项。
- 旧文件保持可读；成功保存后写成新结构。

恢复默认会恢复本设计列出的全部默认值。卸载功能已经删除应用数据目录，因此新设置仍会随一键卸载删除。

### 4.2 工作簿读取

读取器先收集所有输出规则实际使用的字段名称，去重后按表头定位列。源数据保留为按字段名称访问的行数据，计算时由每个输出项读取自己的字段。

字段可移动、前后可插入无关列。字段名称继续精确匹配，不自动猜测。相同字段可以被多个输出项使用，不再因为配置中重复出现而报错。

### 4.3 历史数据

设置变化不会改写 2026 年 8 月以前的冻结基线。下次生成继续按现有计划重算最新完整 Week、前一个 Week和缺失 Week，并把新规则应用到这些可更新周期。

## 5. 校验与错误处理

- 工作表名称和必需计算字段不能为空；表头行必须在 Excel 有效范围内。
- 可选筛选必须同时填写字段和值或同时留空。
- 百分比必须在 `0%` 至 `100%` 之间；计息天数必须为非负整数。
- 资金渠道名称不可重复。
- 找不到工作表或字段时，错误信息同时指出数据源、输出项和当前配置值。
- 日期、金额及公式缓存缺失继续使用现有严格校验，防止生成错误报表。
- 保存失败时保留旧设置，窗口不关闭。

## 6. GitHub Releases 更新

### 6.1 发布流程

GitHub 仓库 `Hailey668866/ledger-report-generator` 是唯一版本信息源，不维护 `latest.json`。

推送 `v*` 标签后，GitHub Actions：

1. 在原生 Apple 芯片和 Intel runner 上运行测试并构建 DMG。
2. 生成每个 DMG 的 SHA-256 文件。
3. 创建对应 GitHub Release。
4. 上传两个 DMG 和两个校验文件。

Release 附件名称固定为：

- `台账报表生成器-arm64.dmg`
- `台账报表生成器-arm64.dmg.sha256`
- `台账报表生成器-x86_64.dmg`
- `台账报表生成器-x86_64.dmg.sha256`

### 6.2 客户端检查

- 应用启动完成后在后台检查一次，不阻塞主界面。
- 应用菜单保留“检查更新”。
- 自动检查失败时不打扰用户；手动检查失败时显示简短错误。
- 使用 GitHub Releases `latest` API 读取版本和附件，忽略草稿及预发布版本。
- 版本号按数字段比较，例如 `0.10.0` 高于 `0.9.0`。
- 已是最新版时，自动检查不提示；手动检查显示“当前已是最新版”。

### 6.3 下载和安装

- 根据 `platform.machine()` 选择 `arm64` 或 `x86_64` 附件。
- 用户确认后下载 DMG 和对应 SHA-256 到应用缓存目录的 `updates` 子目录。
- 下载过程显示进度，并允许取消。
- 校验失败时删除本次临时下载并拒绝打开。
- 校验成功后使用 macOS `open` 命令打开 DMG，用户自行把新版应用拖入“应用程序”完成替换。
- 不静默替换正在运行的应用，不自动删除用户文件。
- 一键卸载继续删除应用缓存，因此也会删除尚未清理的更新安装包。

网络请求只发送 GitHub API 所需的普通 HTTPS 请求，不上传台账、设置、历史或导出文件。

## 7. 测试与验收

- 旧设置迁移后，真实样例结果与当前版本一致。
- 每个经营汇总输出项修改字段后只影响该输出项。
- 自营项目三个计算列使用不同日期、筛选和汇总字段时分别生效。
- 留空筛选对可停用筛选；半填写、缺少字段和非法参数不能保存。
- 自营项目显示名称、项目周期和利润率测算修改后同时反映到预览、Excel 和 PNG。
- 冻结基线和 Week 更新规则保持现有测试结果。
- 自动检查不阻塞启动，离线时不影响报表功能。
- arm64 和 x86_64 分别选择正确附件，版本比较正确。
- 下载必须通过对应 SHA-256 才能打开。
- GitHub tag 构建能创建包含四个固定名称附件的 Release。
- 全量测试、Ruff、格式检查和两种 macOS 构建通过。
